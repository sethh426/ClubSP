# ClubSP Hit List

The **Hit List** is the durable index of user-named systems, operations, protocols, commands, and strategic constructs that should remain easy to retrieve at any time.

## Named systems / constructs

1. **Sentras** — governed source-intelligence units that monitor/query external sources and feed normalized evidence into ClubSP.
2. **Meta-Sentras** — source-discovery, quarantine, schema-probe, usefulness, health, drift, and source-gap intelligence that expands and maintains the Sentra fabric.
3. **Hit List** — this registry itself; add every explicitly user-named command/system/operation here rather than relying on memory alone.

## Named operations

1. **Operation Spike** — an ideation operation. Every Spike returns exactly **3 high-leverage, non-obvious technology ideas** designed to improve ClubSP materially. Ideas should be evaluated for leverage, implementation path, dependencies, risk/cost, and how they connect to existing ClubSP systems before being promoted into the roadmap.

## Named reusable commands / protocols

1. **Protocol Highland** — previously established reusable protocol for the Flow project. Retained here as a cross-project named command; its original project scope remains Flow unless explicitly adapted to ClubSP.

## Hit List rules

- Add an item when the user explicitly names a system, operation, protocol, or reusable command.
- Preserve the exact user-given name.
- Do not invent missing command names.
- Cross-project items must retain their original scope unless the user explicitly changes it.
- A Hit List item can have implementation status: concept, planned, building, active, paused, or retired.
- When the user asks to "show/pop up the Hit List," return the current named registry and statuses.
- Operation Spike ideas do **not** automatically enter the Hit List unless the user names/adopts them.
